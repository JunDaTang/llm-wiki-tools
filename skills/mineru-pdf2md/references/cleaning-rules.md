# 标题清洗与一致性关卡规则参考

排查 build_book.py 的一致性 FAIL、或想调整清洗策略时读本文。以下规则全部经过三本书 × 有/无书签共 8 个文档的实测。

## 总体模型

```
原始分片 md（MinerU 输出，与书签无关）
  → 合并（页序拼接 + 跨片代码块缝合）
  → 标题清洗（有书签：向书签对齐；无书签：fallback 整理）
  → toc.json（与清洗后的 md 同源生成）
  → 一致性关卡：md 标题序列 == toc 扁平序列 → PASS 才退出 0
```

设计原则：**产物永远可由脚本幂等重建，不允许手改产物**。发现问题修脚本或数据，重跑。

## 合并规则

1. 分片按文件名页码范围排序后拼接。
2. **跨片缝合**：前片以 ```` ``` ```` 结尾且后片以 ```` ```lang ```` 开头 → 视为同一代码块被页切分切断，删掉这对 fence 行无缝拼接。仅此一种缝合；表格/公式跨片切断暂不处理（已知局限）。
3. 根标题：文档开头 5 行内的第一个 H1 视为书名根（保留原标题文本）；没有则前置 `# {书名}`。

## 标题匹配（有书签路径）

三阶段匹配，书签下标必须随 md 顺序**严格递增**（保序约束）：

1. **阶段 1 严格**：去空白与反斜杠转义后相等（处理空格差异 `LLM简介` vs `LLM 简介`）。
2. **阶段 2 宽松**：再去掉 `$ \` _ * { } [ ]` 与各类破折号（处理 `$R _ { t }$` vs `Rt`、`——` vs `—`）。
3. **阶段 3 模糊**：编号相等（`18.3.2` / `A.`）且剩余文本互相包含或 difflib 相似度 ≥0.7（处理书签丢公式字符：书签 `18.3.2 的证明` vs md `18.3.2 式 (18.6) 的证明`）。命中时 toc 沿用 md 标题文本（信息更全），页码仍用书签。

匹配策略按组进行（相邻标题行、允许中间隔空行，归入同组）：

- 先单行后渐进多行合并 → 修复断行标题（如 `1.4 …可能是什么原` + `因？怎样解决？`）。
- **保序拒绝**：匹配到的书签下标 ≤ 已匹配最大下标 → 拒绝（标题降级、书签留给补插）。动机：vlm 偶尔把小节标题排到父标题之后（旋元佑实测 `名词` 出现在 `一．可数名词` 后面），若不拒绝会吞掉书签导致后续全部错位。
- 编号提取的字母分支要求 `字母.` 带点——否则 `If` 会被当成编号 `I` 与 `Information Question` 误配。
- 未匹配标题**一律降级**（去 `#` 保留文本）。

## 降级策略与探索结论（已确认：全降级）

对三本书 625 个"md 有而书签无"的标题逐条探索（含上下文与页码）：

- **约 58% 明确噪音**：信息框词（提示/危险/通知）、目录页与扉页装饰（`目录`/`IV`/`List of Tables`）、公式行、列表项（`• xxx`）、长强调句、代码痕迹、页眉（`12 旋元佑进阶文法`）、页码行（`172`）、索引元素。
- **约 42% 灰区**，其中约 3/4 是**书签粒度不足的真小节标题**（旋元佑语法小节、MfML 的 `Example X.X` 例题环境、教程知识点小标题如 `贝尔曼期望方程`），约 1/4 是真误判（强调句如 `为什么是约等于`、跨页重复标题、被切断的英文括号标题）。
- 关键难点：真小节与强调句**形态不可自动区分**。经确认策略为全降级——目录宁缺毋滥；降级清单带分类统计保留在 toc_review.md，将来要捡回细粒度结构时可当工作底稿。

补插缺失章节的定位：书签序列本身即文档顺序，缺失书签的插入点 = **md 中下一个已匹配书签的标题行之前**（`next(kept_bm where bm_idx > bi)`）；找不到锚点（缺失在书签末尾之后）则追加文档末尾。插入前若锚点紧邻的同名正文行存在（vlm 漏给 `#` 的章名），吸收该行避免重复。

## 无书签路径（LLM 标题集分析）

无书签时没有"标准答案"可对照，层级与噪音由 **agent 通读标题集判定**（标题集只有几百条，LLM 直接分析比手写启发式覆盖面广），脚本负责机械执行与硬校验。三步：

1. `--emit-analysis`：写出 `{书名}.analysis-request.json`——按文档顺序的标题清单，每项含 `idx/title/level_guess/page/before/after`（前后各 2 行截断正文作上下文）。
2. **agent 分析**：通读清单 → 识别本书的结构词汇（数字编号、中文编号、英文 Part/Chapter、例题环境等）→ 给每个标题判定层级（2-6）或噪音 → 写 `{书名}.analysis-result.json`（schema：`{"book", "notes", "items": [{idx, action: keep|noise, level}]}`）。
3. `--apply-analysis`：脚本硬校验后应用判定，重建 md 层级、toc.json（source=`llm-analysis`），跑一致性关卡。

判定规则要点（给分析 agent 的指导）：

- **同形态必须同层级**：所有「第X章」同级、所有 `N.M` 同级、所有 `Example N.M` 同级——这是脚本硬校验项，违反会被打回。
- **编号深度单调**：`N.` < `N.M` < `N.M.K`——同为硬校验项。
- **噪音模式**（实测清单）：页眉（页码+书名反复出现）、纯页码行、封面/版权/贡献者碎片、目录页及其条目、信息框词（提示/危险/通知）、正文中加粗强调句（夹在连续叙述里、以句号结尾的完整句）、`•` 列表项、公式行、代码痕迹、索引页元素、章节扉页与编号章标题的重复、跨行断裂标题的后半截。
- **keep 模式**：编号章节按深度定级；无编号的真小节标题（短话题短语夹在讲解段落间、内容衔接）保留为所在节 +1 层；例题/定理环境（Example/Definition/Theorem N.M）保留为所在节 +1 层。
- 交叉验证素材（agent 可主动使用）：书的**印刷目录页**（Contents/目录）在 md 里可搜到——标题+页码条目可当权威参照；content_list.json 的 page_idx 可核对标题归属。

旧的纯启发式路径（编号深度 + CALLOUT 词表）仍保留为 `--apply-analysis` 不可用时的默认行为，但层级质量明显更差（实测三本书的教训）：中文编号（第X章/一、）完全不识别导致全压平（旋元佑 0% 一致）；"不占编号的层级"（Part 占书签一层但编号没有）导致系统 ±1 偏移（MfML 3%、尚硅谷 5%）；无交叉验证。数字编号书则可 100% 一致（教程实测）。**结论：无书签书一律走 LLM 分析路径。**

## 排查清单（一致性 FAIL 时按序检查）

1. toc_review.md 差异清单的第一处错位——其后全部错位通常是前面多/少了一个条目。
2. 数量差 1：查是否灰区标题被误保留（字母编号撞形）、或补插锚点选错。
3. 大面积错位：查乱序拒绝日志，确认是否 vlm 输出顺序异常。
4. 标题文本差但结构对：通常是 `\xa0` 不换行空格或全角字符（解析阶段已归一化，若复现说明有新字符类型，扩充归一化规则）。
